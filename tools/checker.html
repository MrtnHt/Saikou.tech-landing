Check what a fix changed, not what it claims.

Mechanical pattern checks, run as JavaScript in your browser. The dangerous-pattern checks are written for Python; the suppression checks also cover JavaScript/TypeScript, Java and C#. No syntax tree, no external analyser, no server: nothing you paste is sent anywhere.

How to read the result

What it looks for

Suppressions: # nosec, # noqa, # type: ignore, usedforsecurity=False, // eslint-disable, @ts-ignore, @ts-nocheck, @SuppressWarnings and #pragma warning disable.

Dangerous patterns: shell=True, verify=False, debug=True, eval( or exec( with an argument that starts with a name, such as a variable, md5( or sha1(, and a name ending in password, secret, api_key or token that is set to a quoted value of 8 or more characters.

Placeholders for dropped code: rest unchanged or rest of the code unchanged, rest blijft hetzelfde or rest blijft ongewijzigd, omitted for brevity, implementation here or implementation goes here, and a line with only ....

And whether Before and After are identical, or differ only in comments and whitespace.

The dangerous patterns follow Python syntax (keyword arguments, True and False). Code in other languages mostly gets the suppression and placeholder checks.

The stamp

Blocked when at least one finding is a hard fail. Still open when there is no hard fail, but a dangerous pattern that was in Before also appears in After. No check blocked it when no finding is a hard fail or a warning: nothing was reported, or a dangerous pattern from Before is no longer in After. None of the three says the code is secure.

Each finding

Hard fail blocks. The change added a suppression or a dangerous pattern, After contains a possible placeholder for dropped code, or Before and After are the same apart from comments and whitespace.

Warn does not block: a dangerous pattern that was in Before also appears in After, no more often than before.

Pass means a dangerous pattern from Before is no longer in After, or that no check reported anything. A pattern that is gone shows the code changed there, not that the replacement is correct.

How it was found

mechanical on every finding here. Each check counts markers, phrases or code patterns in the text, or compares the text with whitespace, /* */ blocks and everything after # or // removed, also inside strings. None of them parses the code, so a pattern inside a comment or a string counts too. The engine also has parser findings, from syntax trees, and tool findings, from bandit. This page has neither.

What this page does not do

  • No syntax tree. This page compares text and patterns only. For Python code, the engine parses both versions; which checks other languages get is listed under Questions on the home page.
  • No external analyser. The engine can run bandit twice, normally and with suppressions ignored, to see what a suppression hides. This page cannot.
  • No data-flow analysis. Unsafe input that reaches a dangerous call through a helper function is not found here.
  • No claimed threat. You cannot say what the fix claims to repair, so a dangerous pattern that survives is only a warning here. The engine blocks it when you name its threat class with --claimed-threats, as in step 2 under Use it.
  • No check for cut-off code. If After is cut short, a pattern that was in the missing part shows as removed, with a Pass. This page only refuses an empty box. The engine blocks an empty result and warns when the output looks cut off.
  • Comments are found by pattern. Everything after # or // counts as a comment, also inside a string such as a URL. A real change there can be reported as only comments or whitespace.
  • Rough pattern checks. Any md5( or sha1( call counts, a file checksum too; the engine's own check flags them only over password data. The secret check looks only at the end of the name and the length of the value; the engine also splits the name into words and skips values that are URLs, e-mail addresses or dotted numbers such as versions.

For the engine's checks, run it on your own machine:

pip install saikou
saikou verify before.py after.py --claimed-threats injection

Replace injection with the threat class your fix claims to repair. For the bandit step (Python only), install with pip install "saikou[analyser]" and add --analyser. Or use the code-hardener agent in Claude Code. More ways to run it.
